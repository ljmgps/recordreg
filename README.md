# RecordReg — 本地录音转写 + 说话人分离

手机录音（mp3 / aac / m4a）批量转文本，自动区分说话人，**全程离线**，输出 Markdown + JSON。

给那种"攒了几百个通话录音、想批量转成文字又不想上传到云"的场景用的。

## 特点

- **完全离线**：模型跑在本机，录音不出硬盘
- **中文识别准**：SenseVoiceSmall，带标点和数字规整
- **说话人分离**：两人对谈自动标出「谁说的」，不依赖云端声纹服务
- **快**：RTX 3050 上整体 RTF ≈ 0.02（84.9 分钟音频约 2 分钟）
- **不重复干活**：按内容哈希去重，中断可续跑
- **有界面**：拖拽文件、批量队列、进度、结果预览、说话人改名、热词纠错

## 系统要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11（脚本为 bat，其他系统需手动执行对应命令） |
| Python | 3.11（`安装环境.bat` 用 uv 自动准备，无需预装） |
| 显卡 | NVIDIA 显卡，4GB 以上显存；无显卡也能跑，用 `--device cpu`，速度约慢 10 倍 |
| 磁盘 | 约 4GB（依赖 2.5GB + 模型 930MB） |
| 内存 | 8GB 以上 |

## 三步开始

1. 双击 **`安装环境.bat`** — 用 uv 建 Python 3.11 环境并装依赖（首次约 2.5GB）
2. 双击 **`下载模型.bat`** — 从 ModelScope 拉取模型到 `models/`（约 930MB）
3. 双击 **`启动.vbs`** — 直接打开界面，无任何命令行黑窗

> 首次运行前可把 `config.example.yaml` 复制为 `config.yaml` 按需修改（不复制也能跑，用默认值）。

> `启动.bat` 也能启动，但会闪一下命令行窗口，主要在排错时用。


- **添加文件夹会递归扫描**子目录，把整个父目录拖进来即可
- 也可以直接把文件/文件夹**拖进窗口**

- **双击任意一行**看转写结果，右侧可以给说话人改名（同步改 Markdown）
- 「设置」里可以维护**热词表**（识别错的词 → 正确写法），下次处理生效

## 命令行（可选）

界面能满足日常使用，做批量脚本时可以用命令行：

```bat
.venv\Scripts\python.exe app\cli.py "D:\录音"              :: 处理整个目录
.venv\Scripts\python.exe app\cli.py "D:\录音" --status     :: 查看索引
.venv\Scripts\python.exe app\cli.py "D:\录音" --force      :: 强制重跑
```

## 输出

每个音频在 `output/` 下平铺生成两个文件：

- `文件名.md` — 源文件名 + 按说话人轮次排列的正文
- `文件名.json` — 全部元数据：时长、语种、说话人统计、逐段的起止时间/文本/说话人/情感

```markdown
# 项目沟通录音

源文件：`项目沟通录音.aac`

**说话人1** `[00:00 → 00:12]`

方案我看过了，整体没问题，就是第三部分的数据还要再核对一下。

**说话人2** `[00:15 → 00:19]`

我这边先确认一下数据来源，明天上午给您反馈。

**说话人1** `[00:20 → 00:29]`

行，那就这么定。确认完把最终版发我一份。
```

想看详细信息查 JSON，想快速读内容看 Markdown。

## 说话人分离

默认按 **2 人对谈**处理（`config.yaml` 的 `speaker.mode: fixed_k`、`k: 2`）。
这是准确率最高的模式：直接告诉算法"只有两个人"，比让它自己猜强得多。

如果录音是 3 人以上会议，把 `mode` 改成 `auto`，程序会自己估计人数（上限 `max_k`）。

**已知限制**：两人同时说话（抢话、重叠）时无法拆分，这一段会归给其中一人。

## 实测数据（RTX 3050 8GB，8 个真实录音）

| 指标 | 结果 |
| --- | --- |
| 总时长 | 84.9 分钟音频 |
| 总耗时 | 3.4 分钟 |
| 整体 RTF | 0.040 |
| 成功率 | 8/8 |
| 显存峰值 | 1.95 GB / 8 GB |

其中 6 个判定为 2 人对谈、2 个判定为单人（其中一个是单方长讲）。
最长的单个文件是 38.8 分钟的微信 aac，处理耗时 95 秒。

按此推算 100 个 3 分钟文件约 12–15 分钟。

## 命令行参数

| 参数 | 说明 |
| --- | --- |
| `-n, --limit N` | 最多处理 N 个文件，先试跑用 |
| `-d, --device` | `auto` / `cuda` / `cpu` |
| `-o, --output` | 输出目录，默认 `output/` |
| `-f, --force` | 忽略索引，强制重跑已处理的文件 |
| `--status` | 查看索引统计与最近处理记录 |
| `--list-only` | 只列出会处理哪些文件，不实际跑 |
| `--keep-cache` | 保留解码后的 WAV，便于排查 |
| `--no-warmup` | 跳过预热 |
| `-v, --verbose` | 打印解码/VAD/识别/声纹的分阶段耗时 |

## 重复处理不会重跑

每个文件的 **sha256** 会记进 `data/app.db`。同一份录音换个目录、改个名字再拖进来，都会被识别为已处理并直接跳过：

```
[已处理] 需求沟通录音.aac（--force 可强制重跑）
待处理 0 个，跳过 2 个（索引中已完成）
```

中断也不会白跑：处理到第 60 个崩了，下次运行会从第 61 个继续。上次异常退出留下的"处理中"状态会在启动时自动重置。

想看一共处理过多少、哪些失败了：

```bat
.venv\Scripts\python.exe app\cli.py --status
```

改了算法或换了模型想全量重来，勾选右上角的 **「强制重跑」** 再点开始（命令行用 `--force`）。程序版本号变化时也会自动重跑。

## 索引数据库

`data/app.db` 只记录「哪些文件处理过」，不存转写内容。实测 **364 个文件占 0.33 MB**——每条记录约 1KB，一万个文件也就 10MB 量级，不会拖慢速度。

唯一会慢慢积累的是：源文件被你删掉或移走后，记录还留着。在 **设置 → 索引数据库** 里：

- **清理失效记录**：删掉源文件已不存在的记录并回收空间（推荐，安全）
- **清空索引**：全部清空。清空后这些文件会被当作新文件重新识别，**转写结果不会被删除**


## 排查

先跑自检：

```bat
.venv\Scripts\python.exe scripts\check_env.py
```

它会逐项报告 Python / torch / CUDA / ffmpeg / 模型 / 目录是否就绪，并给出修复建议。

模型下载中断了？直接重跑 `下载模型.bat`，支持断点续传。

### 安装失败时

依赖安装有几个坑（funasr 版本、oss2、antlr4），已固化在 `安装环境.bat` 里，**请务必用脚本装，不要手工 pip install**。
如果某一步失败，把报错贴出来；已知问题与处理方式记录在 `docs/DESIGN.md` 的 §11.3.1。

## 依赖的开源模型

本仓库**不包含**模型权重。首次运行 `下载模型.bat` 会从 ModelScope 下载到 `models/`：

| 模型 | 用途 | 出处 |
| --- | --- | --- |
| SenseVoiceSmall | 语音识别（中英日韩粤） | FunAudioLLM |
| fsmn-vad-zh-cn-16k-common | 语音端点检测（断句） | 达摩院 FunASR |
| speech_campplus_sv_zh-cn_16k-common | 说话人声纹特征 | 3D-Speaker |

使用本项目时请一并遵守上述模型各自的开源许可。
